# Solution Strategy — Commerce Analytics Tool (CAT) Clone

> **Problem Solver Enhanced** | Frameworks: SCQA, First Principles, 5 Whys, Game Theory, Second-Order, TRIZ

---

## Problem Statement (SCQA)

**Situation:**
FMCG-бренды и производители продают товары через 110+ цифровых платформ (маркетплейсы, интернет-магазины, дарксторы). Российский e-commerce достиг 11.3 трлн руб. с ростом 36% г/г. Каждый товар имеет карточку с контентом (изображения, описание, состав), ценой, остатками и отзывами.

**Complication:**
Бренды не контролируют то, что происходит с их товарами на полке ежедневно:
- Карточки товаров отклоняются от эталона (неверные изображения, устаревшие описания)
- Дистрибуция не соответствует плану (товара нет в торговых точках где должен быть)
- Конкуренты снижают цены / запускают промо — бренд реагирует с опозданием
- Отзывы накапливаются без систематического анализа
- Ручной мониторинг 110+ платформ нескалируем: занимает 100+ человеко-часов/неделю

**Question:**
Как FMCG-бренд может получать ежедневную, актуальную, структурированную картину своего присутствия на 110+ цифровых платформах без армии аналитиков?

**Answer:**
Автоматизированная SaaS-платформа для мониторинга онлайн-полки с ML-оценкой контента, трекингом дистрибуции, анализом конкурентов и отзывов с генерацией структурированных Excel-отчётов и алёртов.

## First Principles Analysis

### Декомпозиция до атомов

**Что реально нужно бренду?**
1. **Знать факт** — что сейчас происходит с товаром на каждой платформе
2. **Сравнить с эталоном** — соответствует ли факт стандарту (план, эталонный контент)
3. **Получить сигнал** — когда отклонение превышает порог → алёрт
4. **Принять решение** — на основе данных, не догадок

**Первичные истины:**
- Данные о товаре находятся на страницах ритейлеров → их можно собрать автоматически
- ML может сравнить изображение/текст с эталоном точнее и быстрее человека
- Временные ряды (цена, остатки) позволяют обнаруживать аномалии автоматически
- Excel — стандарт коммуникации в FMCG-среде → отчёты должны быть в Excel

**Вывод:**
Система = Сборщик данных (scraper) + Сравниватель с эталоном (ML) + Детектор аномалий + Генератор отчётов. Ничего магического, всё технически зрелое.

## Root Cause Analysis (5 Whys)

**Проблема: Бренд теряет продажи из-за несоответствия карточки товара стандарту на маркетплейсе**

1. **Почему карточка не соответствует?** → Ритейлер изменил контент или не обновил при замене SKU
2. **Почему это не заметили сразу?** → Нет автоматического мониторинга карточек
3. **Почему нет мониторинга?** → Ручная проверка 110 платформ × 1000 SKU = нереально
4. **Почему не автоматизировали раньше?** → Нет готового инструмента, заточенного под производителей (не продавцов)
5. **Корневая причина:** Рынок аналитики маркетплейсов ориентирован на **продавцов** (seller tools), не на **производителей/бренды** (brand/manufacturer tools)

**Решение:** Создать инструмент, специально спроектированный для brand-side пользователей.

## Game Theory Analysis

### Ключевые игроки

| Игрок | Интерес | Ограничения |
|-------|---------|-------------|
| **FMCG-бренд** | Максимизировать продажи, доля полки | Бюджет, команда |
| **Ритейлер/Маркетплейс** | Трафик, GMV → не всегда хочет раскрывать данные | Закрытые API |
| **Конкурент** | Захватить полку бренда | Те же ограничения |
| **Easy Commerce / CAT** | SaaS-выручка, retention | Качество данных, scraping риски |
| **Регулятор** | Честная конкуренция | Anti-scraping laws |

### Nash Equilibrium

- Ритейлеры закрывают API → скрейпинг остаётся основным методом
- Бренды платят за CAT → экономят на аналитиках (ROI положительный при >100 SKU)
- Конкуренты не имеют доступа к данным CAT → first-mover advantage

### Стратегические выводы

- **Барьер входа**: глубокая интеграция в рабочие процессы клиента (Excel-отчёты в привычном формате)
- **Lock-in**: эталонные данные клиента хранятся в системе → уход = потеря истории
- **Network effect**: чем больше клиентов, тем лучше бенчмарки категорий (аноним. агрегация)

## Second-Order Effects

| Первичный эффект | Второй порядок | Третий порядок |
|-----------------|----------------|----------------|
| Бренд видит несоответствие контента → исправляет | Карточки становятся лучше → конверсия растёт | Ритейлер видит рост → охотнее сотрудничает с брендом |
| Алёрт о скидке конкурента → бренд реагирует быстро | Промо-войны становятся более динамичными | Давление на маржу отрасли |
| Анализ отзывов → Product team улучшает продукт | Меньше негативных отзывов → лучше рейтинг | Органическое повышение позиций в поиске |
| Автоматический мониторинг дистрибуции | Логистическая команда реагирует раньше | Снижение stockout → +X% выручки |

## Contradictions Resolved (TRIZ)

| Противоречие | TRIZ Принцип | Решение |
|-------------|-------------|---------|
| Нужны данные в реальном времени vs ограничения scraping | Принцип 10 (Предварительное действие) | Приоритизация критичных SKU/платформ, батчевый сбор по расписанию |
| Полный охват 110+ платформ vs скорость обработки | Принцип 35 (Трансформация параметров) | Распределённая очередь задач (Celery), горизонтальное масштабирование |
| Точное ML-сравнение vs вычислительная стоимость | Принцип 28 (Замена механической системы) | Кэширование embeddings, incremental update |
| Excel-формат (legacy) vs современный дашборд | Принцип 1 (Сегментация) | Оба: Excel-экспорт + веб-дашборд |
| Кастомные эталоны клиента vs стандартизация | Принцип 3 (Локальное качество) | Гибкая конфигурация метрик per-brand |

## Recommended Approach

### Архитектурная стратегия

**Distributed Monolith в Monorepo** — оптимальный выбор:
- Единая кодовая база → проще поддерживать на старте
- Разделение по доменам (scraper / processor / reporter / api / frontend)
- Готовность к микросервисам при росте нагрузки

### Поэтапная разработка

**MVP (Phase 1):**
- 5-10 ключевых платформ (WB, Ozon, Самокат, Лента, ЯМ)
- Content Score (image + description + composition)
- Stock monitoring (план/факт дистрибуция)
- Excel-экспорт (3 формата из репозитория)
- Email-алёрты (цены конкурентов)

**v1.0 (Phase 2):**
- 50+ платформ
- Reviews NLP (ruBERT sentiment)
- Веб-дашборд (React)
- Multi-brand / multi-client поддержка
- API для интеграций

**v2.0 (Phase 3):**
- 110+ платформ
- Predictive analytics (forecast stockout)
- Generative content recommendations
- Agentic alerts (auto-action suggestions)

## Risk Assessment

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Ритейлер блокирует scraping | Высокая | Высокое | Ротация IP/UA, резервные источники, официальные API где доступны |
| Изменение структуры страниц ритейлера | Высокая | Среднее | Модульные scrapers, мониторинг health checks, быстрый hotfix процесс |
| Точность ML < ожидаемой | Средняя | Высокое | Итеративное улучшение, human-in-the-loop для edge cases |
| Конкурент (MPSTATS) выходит в сегмент брендов | Средняя | Высокое | Глубокий product lock-in, уникальные фичи (план/факт, эталоны) |
| Юридические риски scraping | Низкая | Высокое | Юридическая экспертиза, terms of service compliance |
| Потеря данных (downtime scraper) | Средняя | Среднее | Retry механизмы, мониторинг, SLA на сбор данных |
