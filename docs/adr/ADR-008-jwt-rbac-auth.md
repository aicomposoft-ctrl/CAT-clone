# ADR-008: JWT + RBAC аутентификация и авторизация

**Дата:** 2026-03-01  
**Статус:** Accepted  
**Авторы:** CAT Team

---

## Контекст

CAT — мультиарендный SaaS с несколькими ролями пользователей. Нужен механизм аутентификации без состояния (stateless) для API, с поддержкой ролевого доступа.

## Рассматриваемые варианты

| Вариант | Stateless | Refresh | Сложность |
|---------|-----------|---------|-----------|
| Session + Cookie | ❌ | N/A | Низкая |
| **JWT (выбран)** | ✅ | ✅ (refresh token) | Средняя |
| OAuth2 (внешний провайдер) | ✅ | ✅ | Высокая |
| API Key only | ✅ | ❌ | Низкая |

## Решение

**Access Token + Refresh Token схема:**

- Access token: TTL **15 минут**, payload = `{user_id, org_id, role}`
- Refresh token: TTL **7 дней**, хранится в httpOnly cookie
- `JWT_SECRET`: обязательная переменная окружения, нет fallback-дефолта, `sys.exit(1)` при отсутствии
- Пароли: bcrypt, cost factor 12, dummy-hash для защиты от timing attack при несуществующем пользователе

**RBAC роли:**

| Роль | Доступ |
|------|--------|
| `admin` | Полный + управление пользователями + биллинг |
| `manager` | CRUD SKU, все данные, экспорт, алерты |
| `viewer` | Только чтение и экспорт |

**Дополнительно:** внешние интеграции используют API Key (SHA-256 hash в БД, полный ключ показывается один раз).

## Последствия

- **Положительные:** stateless — API масштабируется горизонтально без shared session store
- **Отрицательные:** access token нельзя инвалидировать до истечения TTL (15 мин — приемлемый компромисс)
- **Rate limiting:** `/auth/login` и `/auth/refresh` — 10 req/min per IP
- **Account lockout:** 5 неудачных попыток → блокировка 15 минут
