# ADR-005: MinIO для хранения изображений (S3-совместимый)

**Дата:** 2026-03-01  
**Статус:** Accepted  
**Авторы:** CAT Team

---

## Контекст

CAT хранит эталонные изображения товаров (reference images) и собранные изображения с площадок. Изображения используются для CLIP-сравнения. Нужно: приватный доступ, S3-совместимый API, self-hosted (данные клиентов не уходят в облако).

## Рассматриваемые варианты

| Вариант | Self-hosted | S3 API | Стоимость |
|---------|-------------|--------|-----------|
| **MinIO (выбран)** | ✅ | ✅ | Бесплатно |
| AWS S3 | ❌ | ✅ (native) | $0.023/GB/мес |
| Yandex Object Storage | ❌ (RU-cloud) | ✅ | ₽2.27/GB/мес |
| Локальная файловая система | ✅ | ❌ | Бесплатно |

## Решение

**MinIO** в Docker Compose, API-совместимость с AWS S3 через `boto3`.

- Все изображения — **приватные** (нет public bucket policy)
- Presigned URL для отображения в UI: TTL 1 час
- Bucket naming: `cat-references-{org_uuid}` (не угадываемые имена)
- Эталонные embeddings кешируются в Redis после первой загрузки (не пересчитываются при каждом сравнении)

```python
# Никогда не возвращать прямой S3 URL — только presigned
url = minio_client.presigned_get_object(bucket, key, expires=timedelta(hours=1))
```

## Последствия

- **Положительные:** данные остаются на VPS клиента, zero vendor lock-in, S3-совместимый API позволяет мигрировать на AWS/YOS без изменения кода
- **Отрицательные:** требует настройки персистентного тома Docker для данных MinIO
- **При миграции в облако:** поменять только `MINIO_ENDPOINT` в `.env`
